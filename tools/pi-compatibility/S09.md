# S09 — ACL bounded file tools in the Pi spike

**Current status: complete with the user-selected 27B model; see [current results](S09_27B.md).** The following records the original 7B failure. The adapter and six deterministic tests pass,
but the bounded real-model read/edit case failed on 2026-09-17. No S10 work began.

## Implementation and deterministic validation

`file-tools.mjs` exposes only `acl_read_file` and `acl_write_file`. A fixed Python
bridge calls the existing ACL `BoundedFileTools` implementation rather than
reimplementing its policy. The adapter captures a copy of the trusted grant;
model arguments cannot supply a workspace, grant, operation or command. The
Python executable and bridge path are host-owned, with JSON stdin and no shell.
This subprocess is an adapter implementation detail, not worker process authority.

The reused implementation preserves exact canonical relative paths, UTF-8/NUL
and 262,144-byte limits, SHA-256/absent write preconditions, atomic replacement,
and rejection of link/reparse traversal and hardlinked writes. Six Node tests
passed with zero skips:

- read/digest, replacement and copied grant;
- outside scope and noncanonical paths, with unchanged protected bytes;
- stale writes and absent-file preconditions;
- invalid UTF-8, NUL, surrogate and size limits;
- hardlinked write and parent-junction rejection;
- rejection of model-supplied authority fields.

The first fixture run rejected Windows short-name temporary roots. Resolving the
trusted temporary base to its canonical path before granting it fixed the fixture;
ACL path enforcement was not weakened. The passing run took about 4.1 seconds.
These tests establish these adapter cases, not OS containment or concurrent
external filesystem-race protection.

## Real-model failure

[Retained real probe evidence](../../docs/evidence/S09_PI_FILE_PROBE.json) records
Pi 0.85.1, Ollama 0.34.1 and the approved qwen2.5-coder:7b model/digest at
http://127.0.0.1:11434/v1. Exactly one HTTP 200 request advertised only the two ACL
custom tools. The response was plain assistant text containing:

```json
{"name": "acl_read_file", "arguments": {"path": "target.txt"}}
```

Pi reported a normal stop but executed **zero tools**. Independent parent-side
validation found no changed paths, the target still `VALUE = 1\n`, and the
protected file unchanged. The required `VALUE = 2\n` artifact was absent, so the
probe correctly returned FAIL despite normal model termination. No text-to-tool
fallback was added. This observation does not establish whether the cause is the
model, its template, Ollama's tool-call parsing, or transport compatibility.

The grant, tool schema, implementation and lock hashes, request destination,
effective tools, final response, byte snapshots and validation are in the evidence.
Retries and compaction were disabled. Limits were four model requests, six tool
calls, 256 output tokens per request, 60-second provider timeout and 180-second
child deadline. This run used one request and zero tool calls. Active context was
4K; effective 32K qualification remains pending. Production dispatch is unchanged.
