## Logging and error handling

- Timestamped request sequence, destination/model, wire payload, HTTP status,
  elapsed time and raw SSE response, capped at 128 KiB per request.
- Pi lifecycle and tool execution events with call IDs and tool error flags.
- Every adapter call records arguments, result, child exit/signal/stderr,
  duration and structured errors, including pre-execution rejection or spawn failure.
- Runtime preflight requests have deadlines and HTTP checks. Missing Python,
  unavailable model, digest mismatch and startup/report failures write FAIL evidence.
- Provider HTTP/network failures retain diagnostic details. Acceptance failures
  identify missing native calls, unsuccessful termination, missing required content
  and workspace scope violations separately.

These verbose logs contain prompts, file contents and tool arguments from the
**disposable qualification fixture**. No authorization headers or inherited
provider credentials are recorded. This is not a general production logging policy.
The bounded response is buffered for diagnostic capture before Pi consumes it;
this probe does not qualify real-time streaming, cancellation or S11 settlement.

Per-request `reasoning_effort: none` explicitly disables thinking for the bounded
probe. Limits remain four requests, six tool calls, 256 output tokens per request,
60-second provider deadline and 180-second child deadline. Retries and automatic
compaction remain disabled. Active server context is **4K**; Pi metadata is 32K
and model-advertised capacity is 256K. Neither establishes effective larger context.
