# S08 — Exact Pi model and endpoint selection

**Result: PASS**, observed 2026-09-17. Pi `0.85.1` on Node `24.19.0`
used the user-approved `qwen2.5-coder:7b` through
`http://127.0.0.1:11434/v1`, served by Ollama `0.34.1`.

| Real request | Observed result |
| --- | --- |
| Exact model and endpoint | HTTP 200, `ACL_S08_OK`, normal stop |
| Nonexistent model at correct endpoint | HTTP 404, model not found |
| Correct model at deliberately invalid API path | HTTP 404, page not found |

Each case issued exactly one traced request with the intended model, destination,
and 32-token output cap. The transport guard rejects alternative destinations or
models, and SDK fallback messages fail the probe. Both negative cases failed
without fallback. The wrong-endpoint case tests an invalid route on the existing
server, not an unreachable port.

[Final machine-readable evidence](../../docs/evidence/S08_PI_MODEL_SELECTION.json)
records model digest, installed package/runtime versions, effective selection,
wire requests, responses, settings/resource/lock/probe hashes and child exits.

## Reproduce

With the S07 dependencies installed and the approved model already present in
Ollama, run from this directory:

```powershell
node selection-probe.mjs
```

This makes three real local requests and writes ignored `selection.local.json`.
It never pulls a model. Each case uses a fresh temporary home, sanitized child
environment, in-memory session, explicit model, no tools, and disabled resource
discovery. Retries and automatic compaction are disabled; provider timeout is
60 seconds and each child deadline is 90 seconds. No production dispatch code
or model-server configuration is changed. Temporary directories are retained.

## Context limitation and initial correction

The model advertises 32,768 tokens, used solely as Pi model metadata. Ollama's
observed active context is **4,096 tokens**. The successful request used 67 total
tokens according to the provider usage report. This is not effective 32K
qualification; server configuration and meaningful retention/tool use remain
S15 requirements if the 32K requirement is retained.

The [initial failed probe](../../docs/evidence/S08_INITIAL_PROBE.json) is retained.
Its initial 4,096-token Pi metadata setting interacted with Pi's 4,096-token
context safety reserve, reducing the actual output cap to one token. The model
returned `ACL` with a length stop. Correcting the metadata to advertised capacity
restored the intended 32-token wire cap; the server context was not changed.
The initial evidence's probe hash identifies that earlier script revision.

S08 qualifies only this bounded selection probe. File tools, outcome handling,
settlement correctness, cancellation, session reopen and compaction remain the
separate S09–S15 tasks; the combined qualification gate remains S16.
