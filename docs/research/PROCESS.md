# Research Process

For each assigned research task:

1. Read `README.md`, `RESEARCH_STATE.md`, `sources.md`, and `watchlist.md`.
2. Work only on the assigned task.
3. Prefer primary sources: project repositories, issues, discussions, documentation, papers, maintainers' posts, and security standards. Use community discussion to find real-world experience and failure reports.
4. Record evidence, publication/update date when available, and a stable source URL.
5. Separate observed fact from inference.
6. Record why each finding matters to ACL or future Vera work.
7. Update the relevant topic file and `catalog.jsonl`.
8. Update `RESEARCH_STATE.md` with completed and next work.
9. Commit only research documentation changes and stop.

## Finding fields

Each substantive finding should capture:
- source and date;
- project/person/community;
- category;
- finding;
- evidence;
- relevance to ACL/Vera;
- possible reuse;
- failure/warning;
- confidence;
- follow-up question.

## Anti-drift

Do not implement code, change ACL governance, run local workers/models, or research the next item unless the current task explicitly asks for it.
