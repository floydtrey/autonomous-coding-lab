# Knowledge Architecture Candidate Invariants

This ledger accumulates evidence-backed **candidate** invariants during the Knowledge Architecture Evidence Campaign. These are not final architecture rules.

## Status meanings

- **candidate** — supported by one bounded task.
- **reinforced** — independently supported by multiple tasks.
- **qualified** — retained with narrower scope after counterevidence.
- **rejected** — evidence showed the formulation was too strong or wrong.

## KA-9 + KA-10 bounded-block recurrence update

- KA-9 and KA-10 were researched as one user-authorized bounded block, with separate reports and source attribution.
- KA-I-046 is new and immediately **reinforced**. OpenAI independently shows that a persisted approval remains final for an invocation while policy can change around it, requiring host-side policy-version invalidation before resume; MCP independently requires authority-relevant continuation state to be bound to principal, expiry and originating method/parameter semantics and requires server-side state when single-use matters.
- OpenAI adds strong positive evidence for generation-bound destructive compaction/replacement (KA-I-035), semantic checkpoint versioning (KA-I-017/018), settled source-input consumption (KA-I-028/032), occurrence lineage through history rewrites (KA-I-036), and old-generation cleanup fencing (KA-I-041).
- MCP adds strong recurrence for stateless transport/application identity separation, per-request authority, exact compatibility profile, tool-origin identity, and protocol/task success versus effect settlement.
- The MCP Filesystems Working Group is retained only as **directional** evidence for resource mutation authority, optimistic concurrency and cache/write coherence; no future proposal is treated as current protocol behavior.
- KA-I-037 remains candidate despite adjacent OpenAI filesystem and MCP Resource evidence because neither independently establishes the complete logical-resource/locator/content-digest formulation.
- KA-I-043–045 remain candidates; KA-10 adds adjacent support but not a full independent match to their existing formulations.
- KA-I-004, KA-I-005, KA-I-007, KA-I-031, KA-I-034, KA-I-037–040 and KA-I-043–045 remain candidates.
- No invariant is promoted to a final architecture rule during the evidence campaign.
